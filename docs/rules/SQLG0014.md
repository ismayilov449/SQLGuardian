# SQLG0014 — Dynamic SQL concatenation

| Field | Value |
|-------|-------|
| Rule ID | SQLG0014 |
| Title | Dynamic SQL string concatenation |
| Category | Security |
| Severity | High |
| Auto-fix | Not supported |
| Tags | dynamic-sql, injection, execute |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Building dynamic SQL with string concatenation (`+`) and executing it risks SQL injection and plan-cache pollution. Prefer parameterized `sp_executesql`.

## Detection

Flag `EXECUTE` / `EXEC` of a string expression that uses binary `+` concatenation, or `EXEC(@var)` patterns where the immediate execute target is a concatenated expression.

## Examples

Bad:

```sql
DECLARE @sql nvarchar(max) = N'SELECT * FROM ' + @table;
EXEC(@sql);
```

Good:

```sql
EXEC sys.sp_executesql N'SELECT Id FROM dbo.Users WHERE Id = @id', N'@id int', @id = @id;
```
