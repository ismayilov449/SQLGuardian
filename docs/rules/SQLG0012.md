# SQLG0012 — Unindexed join column

| Field | Value |
|-------|-------|
| Rule ID | SQLG0012 |
| Title | Unindexed join column |
| Category | Performance |
| Severity | Medium |
| Auto-fix | Suggested index guidance |
| Tags | schema, index, join |
| Requires | Catalog snapshot (`--connection`) |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Equality join (or equality filter) columns that are not leading index keys can force scans on larger tables.

## Detection

Requires a schema snapshot attached to analysis.

1. Collect equality comparisons between two column references.
2. Resolve qualifiers via table aliases / names in the script.
3. If the resolved table has ≥ 1,000 approximate rows and the column is not a leading index key, flag it.

Primary-key sides are usually indexed already and are not flagged.

## False positives

- Low-selectivity columns where a heap scan is acceptable
- Temporary / small tables under the row threshold

## Examples

Bad (no index on `Orders.CustomerId`, schema attached):

```sql
SELECT o.Id
FROM dbo.Orders AS o
INNER JOIN dbo.Customers AS c ON o.CustomerId = c.Id;
```

Good:

```sql
CREATE NONCLUSTERED INDEX IX_Orders_CustomerId
ON dbo.Orders (CustomerId);
```
