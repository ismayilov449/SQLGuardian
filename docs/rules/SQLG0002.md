# SQLG0002 — UPDATE/DELETE without WHERE

| Field | Value |
|-------|-------|
| Rule ID | SQLG0002 |
| Title | UPDATE/DELETE without WHERE |
| Category | Correctness |
| Severity | Critical |
| Auto-fix | Not supported |
| Tags | update, delete, where, data-loss |
| Database compatibility | SQL Server, Azure SQL |

## Problem

An `UPDATE` or `DELETE` without a `WHERE` clause affects every row in the target and is a common cause of accidental data loss.

## Detection

Flag `UpdateStatement` / `DeleteStatement` whose specification has a null `WhereClause`.

## False positives

- Intentional full-table maintenance scripts (suppress per-file or disable the rule in config)
- Statements that use a join filter only in `FROM` without `WHERE` are still flagged (prefer explicit `WHERE`)

## Examples

Bad:

```sql
DELETE FROM dbo.Users;
UPDATE dbo.Users SET IsActive = 0;
```

Good:

```sql
DELETE FROM dbo.Users WHERE Id = @Id;
UPDATE dbo.Users SET IsActive = 0 WHERE Id = @Id;
```
