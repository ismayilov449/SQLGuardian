# SQLG0011 — Foreign key without supporting index

| Field | Value |
|-------|-------|
| Rule ID | SQLG0011 |
| Title | Foreign key without supporting index |
| Category | Performance |
| Severity | Medium |
| Auto-fix | Suggested `CREATE INDEX` text |
| Tags | schema, index, foreign-key, join |
| Requires | Catalog snapshot (`--connection` / Catalog Scan) |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Foreign key columns that are not the **leading key** of any index often cause nested-loop joins, cascades, and lookups to scan the child table.

## Detection

Requires a schema snapshot (metadata + approximate row counts from `sys.partitions` — never table data).

1. Load FKs and indexes from the catalog.
2. For each FK on a table with approximate row count ≥ 1,000:
   - Flag when the FK parent column list is not a leading-key prefix of any index (including PK/unique).
3. Script mode: only tables referenced in the script. Catalog mode (`sqlguardian catalog`): all tables.

## False positives

- Intentionally tiny / staging tables (row-count threshold skips most of these)
- Covering strategies that use a different leading column intentionally

## Examples

Bad (no index on `Orders.CustomerId`):

```sql
-- Catalog finding when FK_Orders_Customers exists without a supporting index
```

Good:

```sql
CREATE NONCLUSTERED INDEX IX_Orders_CustomerId
ON dbo.Orders (CustomerId);
```
