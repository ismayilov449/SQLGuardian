# SQLG0003 — NOLOCK hint

| Field | Value |
|-------|-------|
| Rule ID | SQLG0003 |
| Title | Avoid NOLOCK table hint |
| Category | Concurrency |
| Severity | High |
| Auto-fix | Not supported |
| Tags | nolock, isolation, dirty-read |
| Database compatibility | SQL Server, Azure SQL |

## Problem

`NOLOCK` / `READUNCOMMITTED` allows dirty reads, missing rows, and duplicate rows under concurrency. It is often used as a performance shortcut that trades correctness.

## Detection

Detect `NamedTableReference` table hints where `TableHintKind` is `NoLock` (and treat `ReadUncommitted` the same).

## False positives

- Rare reporting queries that explicitly accept dirty reads (suppress with config)

## Examples

Bad:

```sql
SELECT Id FROM dbo.Users WITH (NOLOCK);
```

Good:

```sql
SELECT Id FROM dbo.Users;
-- Or use an appropriate isolation level / snapshot as a deliberate choice
```
