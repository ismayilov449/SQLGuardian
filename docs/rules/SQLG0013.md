# SQLG0013 — Non-SARGable function on column

| Field | Value |
|-------|-------|
| Rule ID | SQLG0013 |
| Title | Non-SARGable function on column |
| Category | Performance |
| Severity | Medium |
| Auto-fix | Not supported |
| Tags | sargable, function, index, where |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Wrapping a column in a function inside `WHERE` / `JOIN` / `HAVING` (e.g. `YEAR(OrderDate)`, `CONVERT(...)`, `UPPER(Name)`) typically prevents index seeks.

## Detection

In comparison / LIKE predicates, flag when one side is a scalar function, `CAST`, or `CONVERT` that references a column, and the other side is not the same pattern on both sides.

## False positives

- Functions on literals/parameters only
- Computed-column / indexed-view designs that intentionally match the expression (suppress via config)

## Examples

Bad:

```sql
SELECT Id FROM dbo.Orders WHERE YEAR(OrderDate) = 2024;
```

Good:

```sql
SELECT Id FROM dbo.Orders
WHERE OrderDate >= '20240101' AND OrderDate < '20250101';
```
