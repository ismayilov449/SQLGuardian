# SQLG0009 — DISTINCT usage

| Field | Value |
|-------|-------|
| Rule ID | SQLG0009 |
| Title | DISTINCT usage |
| Category | Performance |
| Severity | Low |
| Auto-fix | Not supported |
| Tags | distinct, duplicate-removal |
| Database compatibility | SQL Server, Azure SQL |

## Problem

`DISTINCT` often hides a join cardinality problem and adds sort/hash cost. Prefer fixing the join or projecting keys that are already unique.

## Detection

Flag `QuerySpecification` nodes where `UniqueRowFilter == Distinct`.

## False positives

- Reporting queries that must de-duplicate by design

## Examples

Bad:

```sql
SELECT DISTINCT u.Email
FROM dbo.Users AS u
INNER JOIN dbo.Orders AS o ON o.UserId = u.Id;
```

Good:

```sql
SELECT u.Email
FROM dbo.Users AS u
WHERE EXISTS (SELECT 1 FROM dbo.Orders AS o WHERE o.UserId = u.Id);
```
