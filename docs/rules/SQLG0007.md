# SQLG0007 — Cursor usage

| Field | Value |
|-------|-------|
| Rule ID | SQLG0007 |
| Title | Avoid cursors |
| Category | Performance |
| Severity | Medium |
| Auto-fix | Not supported |
| Tags | cursor, row-by-row, rbar |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Cursors encourage row-by-row processing and are usually slower than set-based alternatives.

## Detection

Flag cursor-related statements: `DeclareCursorStatement`, `OpenCursorStatement`, `FetchCursorStatement`, and `CloseCursorStatement` when present.

## False positives

- Rare administrative scripts where a cursor is the clearest option (suppress via config)

## Examples

Bad:

```sql
DECLARE c CURSOR FOR SELECT Id FROM dbo.Users;
OPEN c;
FETCH NEXT FROM c INTO @Id;
CLOSE c;
DEALLOCATE c;
```

Good:

```sql
-- Prefer set-based UPDATE/INSERT/DELETE or other set operations
UPDATE dbo.Users SET IsActive = 1 WHERE IsActive = 0;
```
