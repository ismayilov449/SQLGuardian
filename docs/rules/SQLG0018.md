# SQLG0018 — Implicit conversion risk

| Field | Value |
|-------|-------|
| Rule ID | SQLG0018 |
| Title | Implicit conversion risk |
| Category | Performance |
| Severity | Medium |
| Auto-fix | Not supported |
| Tags | schema, conversion, sargable |
| Database compatibility | SQL Server, Azure SQL |

## Problem

Comparing a column to a literal/parameter of a different type (e.g. `varchar` column vs `int` literal) can force scans via implicit conversion.

## Detection

Requires schema snapshot with column data types. Flag equality comparisons between a resolved column and a literal whose inferred type family conflicts with the column type.

## Examples

Bad (column `Code` is `varchar`):

```sql
SELECT Id FROM dbo.Items WHERE Code = 123;
```

Good:

```sql
SELECT Id FROM dbo.Items WHERE Code = '123';
```
